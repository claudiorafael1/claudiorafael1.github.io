# Revisão editorial do portfólio — Fael Gomes

## O objetivo

O portfólio fala com uma pessoa que quer entender rapidamente **qual problema foi atacado, que tecnologia foi usada e onde conferir a implementação**. Nenhuma frase depende de uma promessa difícil de comprovar.

## Exemplos de mudança

| Antes | Depois | Por quê |
|---|---|---|
| “Ideias viram sistemas. E sistemas geram impacto.” | “Do backend ao hardware. Meu trabalho está no código.” | Especialidade concreta e prova verificável, sem “impacto” não medido. |
| “Curiosidade técnica. Entrega concreta.” | “Gosto de entender como tudo se conecta.” | Voz pessoal, menos tom de anúncio. |
| “Ferramentas são o meio. Resolver é o fim.” | “O que uso na prática.” | Linguagem simples e fácil de localizar. |
| “Tem uma ideia interessante? Vamos construir.” | “O código está aberto. A conversa também.” | Convite discreto, ligado ao conteúdo da página. |

## Como melhorar um cartão de projeto no futuro

1. **Uma frase sobre a função:** “Conecta Cardputer e navegadores por um servidor em Python.”
2. **Um detalhe que diferencia:** “Inclui aprovação de pareamento e autenticação por dispositivo.”
3. **Uma prova:** README, screenshot real, teste executável, demonstração ou link para o código.
4. **Limitações com honestidade:** especificar quando algo é experimento, não é LLM ou não possui criptografia ponta a ponta.

A regra é: **se um avaliador abrir o GitHub, a descrição deve continuar verdadeira.**

## Referências consultadas

- [Sebastián Ramírez / tiangolo](https://github.com/tiangolo): se apresenta a partir dos projetos que criou e dos assuntos em que trabalha, com frases diretas e links.
- [Sindre Sorhus / sindresorhus](https://github.com/sindresorhus): bio curta com tecnologias e tipos de ferramentas que produz.
- [Simon Willison / simonw](https://github.com/simonw): identifica o trabalho atual e apresenta projetos demonstráveis e atualizados.
- [Addy Osmani / addyosmani](https://github.com/addyosmani): descrição curta do foco profissional e repositórios com proposta clara.
- [GitHub Docs: Using your GitHub profile to enhance your resume](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume): priorizar de 3 a 5 projetos, documentação, exemplos, testes e clareza para avaliadores.

As referências orientaram **a estrutura da mensagem**, não foram copiadas. Não foi feita uma auditoria independente de todos os arquivos dos quatro repositórios nesta revisão; confirme o escopo técnico antes de publicar alegações novas.

## Como publicar

Se ainda não publicou, rode `bash publicar.sh` na pasta extraída. Se o site já está publicado e a pasta tem o Git remoto configurado, use `bash atualizar.sh`. Veja `GUIA_PUBLICACAO.md`.
